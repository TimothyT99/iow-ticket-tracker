Typical resale pattern for major UK festivals:
Prices start high → dip in the 4–6 week window (ideal buy zone) → spike sharply in the final 10 days. Lineup announcements in Sep/Oct and Jan/Feb typically cause a short-term price spike (2–3 weeks) followed by a correction. Selling just before or just after an announcement is usually the strongest exit.

How It Works

Architecture
GitHub Actions runs the Playwright scraper hourly during UK hours (06:00–22:00 UTC = 07:00–23:00 BST) in peak season (Mar–Jun), and once daily in the off-season. Each run commits new data to data/snapshots.json, which triggers a Netlify rebuild automatically.


Running a manual scrape
Go to your GitHub repo → Actions → "Scrape Twickets Ticket Prices" → Run workflow. Or locally: cd scraper && npm install && npx playwright install chromium && node scrape.js


Adding IoW 2027
When 2027 tickets go on sale, go to Twickets, find the event page, and copy the event ID from the URL (the long number after /event/). Add it to data/events.json under the 2027 key along with the face value. The scraper will automatically start collecting 2027 data from the next run.


Updating announcement dates
Edit data/events.json and update the announcements array with confirmed dates and a brief description of who was announced. These appear as markers on the trend chart.


Camping vs non-camping tickets
The IoW Festival Twickets page lists two types of adult weekend ticket: Camping (weekend access + campsite) and Non-Camping (weekend access only). Ticketmaster prices them differently (~£368 vs ~£285 in 2026), but on resale they share the same listing page and compete in the same pool — some buyers are indifferent. The scraper captures both and tags each listing. Stats, signals, and the primary trend line use camping tickets only (directly comparable to the Ticketmaster camping price). Non-camping is shown as a separate, lighter series on the trends chart and flagged with a badge in all tables.


Fingerprinting & sold inference
Listing IDs are not exposed by Twickets, so each listing is identified by price|qty|tier. When a fingerprint disappears between snapshots it's logged as inferred sold. Unique fingerprints give high-confidence signals. Listings marked "Accepting Offers" that disappear likely sold below asking. Listings that disappear above Ticketmaster all-in price are more likely removed/relisted than genuinely sold — the outcome column in the Sold log flags this.


Scrape frequency strategy
Every 15 minutes during UK waking hours (07:00–23:00 BST) in peak season, triggered by cron-job.org → GitHub workflow_dispatch. GitHub Actions hourly schedule acts as fallback. Off-season: once daily. Trigger a manual run anytime from the GitHub Actions tab.
