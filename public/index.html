Typical resale pattern for major UK festivals:
Prices start high → dip in the 4–6 week window (ideal buy zone) → spike sharply in the final 10 days. Selling just before or just after an announcement is usually the strongest exit.

How It Works

Architecture
GitHub Actions runs the Playwright scraper on a schedule every 3 days, commits new data to data/snapshots.json, and the commit triggers a Netlify rebuild. You never need to run anything manually.


Running a manual scrape
Go to your GitHub repo → Actions → "Scrape Twickets Ticket Prices" → Run workflow. Or locally: cd scraper && npm install && npx playwright install chromium && node scrape.js


Adding IoW 2027
When 2027 tickets go on sale, go to Twickets, find the event page, and copy the event ID from the URL (the long number after /event/). Add it to data/events.json under the 2027 key along with the face value. The scraper will automatically start collecting 2027 data from the next run.


Updating announcement dates
Edit data/events.json and update the announcements array with confirmed dates and a brief description of who was announced. These appear as markers on the trend chart.


Fingerprinting & sold inference
Listing IDs are not exposed by Twickets, so each listing is identified by price|qty|tier. Unique fingerprints give high-confidence sold signals. Listings marked "Accepting Offers" that disappear likely sold below asking.


Scrape frequency strategy
Every 3 days is a good default. Consider running daily in the 2 weeks before the festival and around announcement dates. The GitHub Actions workflow supports manual triggers for this.
